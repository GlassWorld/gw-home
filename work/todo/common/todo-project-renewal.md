## Goal

- PC·모바일에서 내 할 일을 등록·조회·수정·완료할 수 있는 반응형 업무 공간을 만든다.
- 디자인·공통 컴포넌트·feature 책임을 정렬하고 일일·주간보고를 제거한다.
- 동일한 TODO 데이터를 간트차트와 완료 통계에서 사용한다. 구현된 정기 요약·개별 메일은 비활성 상태로 보존한다.

## Scope

### 확정 요구사항

- Nuxt3·TypeScript·Spring Boot·MyBatis와 기존 모듈 경계를 유지한다.
- 공통 디자인과 모바일 대응, 페이지 조합 중심 구조, 기존 컴포넌트 우선 재사용.
- WorkUnit·TODO 트리 재사용, 여러 업무의 내 할 일 통합 조회, 모바일 CRUD와 완료 취소.
- 정기 요약·개별 메일은 구현을 보존하되 사용자 결정에 따라 실제 발송을 사용하지 않는다. 제공자 연결과 발송 검증은 현재 완료 조건에서 제외한다.
- 일일·주간보고의 작성·조회·공개 조회·관리자 운영·전용 생성 로직 제거.
- 일정 조회용 간트차트와 완료 건수·완료율·업무별 진행률 그래프.
- 기존 인증·권한·공지·게시판·금고·Git 계정과 저장소 연결 등 유지 대상 기능 보존.

### 제외 및 분리

- 1단계에서 백엔드·API 계약·SQL·데이터 변경, 실제 메일 발송, 배포, 커밋.
- 보고서 데이터의 물리 삭제, 기존 데이터를 TODO나 완료 실적으로 자동 변환하는 작업.
- 간트 드래그 일정 변경·작업 간 선후행 의존성, 네이티브 앱·오프라인·브라우저 푸시.
- 업무 담당자 협업 모델·새 권한 체계·관련 없는 도메인 로직 재작성.
- 정적 문서만 보고 기존 기능의 실행 검증까지 완료했다고 표시하는 것.

### 공통 구현 제약

- `.ai/CORE_RULES.md`, `docs/frontend/frontend-rules.md`, `docs/backend/backend-rules.md`, `docs/backend/database.md`, `docs/common/api-contract.md`를 따른다.
- API 외부 식별자는 uuid, JSON 응답은 snake_case, 프런트 모델은 명시적 타입과 API 매핑을 사용한다. `any` 금지.
- Mapper 인터페이스·XML은 infra-db, VO/JVO는 share, DTO·Controller·Service·Convert는 api에 둔다. JPA·Querydsl을 도입하지 않는다.
- 새 시각 필드는 TIMESTAMPTZ를 사용한다. 기존 시작일·마감일 DATE는 달력 날짜로 유지한다.

- 사용자의 시간대와 기준 시각을 목록·메일·통계·지연 계산에 함께 적용한다.

#### 2단계 API 계약

- 목록/요약 query: `workUnitUuid`(UUID, 선택), `keyword`(최대 200자), `group`(`ALL/TODAY/UPCOMING/OVERDUE/COMPLETED/UNSCHEDULED`), `includeInactive`(기본 false), `fromDate/toDate`(ISO DATE, 선택), `timeZone`(기본 Asia/Seoul), `page`(1부터, 최대 1,000,000), `size`(기본 20, 최대 100).
- 목록 반환: `ApiResponse<PageResponse<WorkTodoListResponse>>`. 항목은 TODO·업무·부모 UUID, 업무명/활성 여부, 제목/내용/일정/정렬, 완료 여부/시각/분류다. 내부 PK를 노출하지 않는다.
- 요약 반환: 총수·오늘·예정·지연·완료·일정 없음·완료 시각 미기록 건수, 현재 완료율, `as_of_date/time_zone`. `group/page/size`는 분류별 요약을 제한하지 않는다.
- 기존 트리 GET/POST/PUT/DELETE에 선택적 `timeZone` query를 추가했다. JSON은 기존 snake_case 계약을 유지하고 노드에 `completed_at`을 추가했다.
- 비로그인 401, 잘못된 분류·페이지·크기·업무 UUID·시간대·역전 기간 400. 다른 소유자의 업무 UUID로 통합 조회하면 빈 결과, 기존 트리 접근은 404다.
- 기본 분류는 전체다. 편집 시 업무 간 이동은 제공하지 않는다. 전체 목록을 만들기 위한 N회 트리 조회는 없으며, 상세/수정/완료 선택 시 해당 업무의 최신 트리만 읽는다.
- 기본 다크모드는 사용자 요청으로 확정했으며 테마 선택 설정을 새로 추가하지 않았다.

#### 데이터와 집계 기준 제안

- 기본 행동·집계 단위는 삭제되지 않은 최하위 TODO다. 부모는 트리 표시와 진행률 계산에 사용하고 건수에 중복 포함하지 않는다.
- 현재 완료율 = 완료 최하위 수 / 전체 최하위 수 × 100. 항목 0개는 0%와 빈 상태로 표시한다. 기존 반올림 규칙을 유지한다.
- WorkUnit의 `IN_PROGRESS / DONE / ON_HOLD`와 TODO의 파생 상태를 다른 필드로 표현한다. 최하위 TODO에 수동 진행중 상태를 새로 추가하지 않는다.
- 오늘: 미완료이고 오늘이 지정 일정 범위 안이거나, 시작일만 있으면 시작일 이후, 마감일만 있으면 마감일 당일인 항목.
- 예정: 미완료이고 시작일이 미래이거나, 시작일 없이 마감일만 미래인 항목. 지연: 미완료이고 마감일이 사용자 기준 오늘보다 이전.
- 완료/지연/오늘/예정 순서로 한 그룹에 배치하고, 날짜가 전혀 없는 항목은 `일정 미지정`으로 표시해 누락을 막는다.
- 기본 목록은 활성 업무를 대상으로 하고 비활성 업무 포함 필터를 제공한다. 통계는 비활성 업무도 기본 포함하되 삭제 항목은 제외하고 적용 필터를 보여준다.
- API 집계에 동일한 필터·시간대·기준 시각을 전달한다. 기본값이 다른 화면을 비교할 때 조건 차이가 드러나야 한다.
- `cmpl_at TIMESTAMPTZ` 컬럼으로 `completed_at` 응답을 제공한다. 서버가 완료 전환 시 기록하며 이미 완료된 항목을 다시 완료해도 변경하지 않는다.
- 완료 취소는 현재 완료 시각을 비우고, 재완료는 새 시각을 기록한다. 현재 유효 완료 기준이므로 이전 날짜의 그래프 건수는 줄어들 수 있다.
- 부모의 자동 완료는 완료 건수에 포함하지 않는다. 자식 추가·삭제·이동에 따른 leaf 변경도 재계산하며, 자동 파생된 완료를 새 실적으로 만들지 않는다.
- 기존 완료 항목의 시각은 null로 유지해 `완료일 미상`으로 표시한다. 현재 완료율에는 포함하지만 기간별 완료 추이에는 넣지 않고 별도 건수를 알린다.
- 진행·지연 현황은 조회 시점 상태, 일·주·월별 완료 추이는 선택 기간의 완료 시각 기준이다. 기간별 역사적 전체 상태를 복원하는 통계로 표현하지 않는다.

### 4. 정기 요약 메일과 개별 알림

#### 현재 결정 — 메일 발송 사용 보류 (2026-10-25)

- 사용자 요청: “발송은 안하는걸로 해서 넘어갈래”. 정기 요약·개별 알림·수신 주소 확인 메일을 실제로 발송하지 않으며, SMTP/OAuth 계정 연결·비밀번호 준비·Node 이식도 진행하지 않는다.
- `WORK_NOTIFICATIONS_ENABLED=false`를 유지한다. 저장소의 기본값과 개인 로컬 예제 모두 false이며, 작업자·확인 메일 요청·SMTP 전송에서 준비 상태를 확인해 비활성 시 발송하지 않는다. 운영 서버 설정을 변경하거나 실제 메일을 발송하지 않았다.
- 이미 작성된 코드·UI·DDL·격리 테스트는 보존한다. 기존 TODO 쓰기가 알림 예약 동기화 테이블을 사용하므로 메일을 꺼도 API 배포 전 해당 SQL은 필요하다. 기능·스키마 전체 제거는 이번 요청에 포함하지 않는다.
- 아래 구현·검증·제공자 연결 기록은 보존용이다. 실제 연결·수신 검증을 리뉴얼 완료의 필수 조건으로 두지 않으며, 메일 연결 없이 후속 5단계 간트차트·완료 통계를 구현했다.

#### 착수 범위와 구현 계약

- 분류 Full-stack / HEAVY. 사용자의 4단계 실행 요청을 승인으로 진행한다. 기존 문서를 갱신하고 코드·격리 테스트까지 구현하며 실제 DB·실수신자 발송·배포는 분리한다.
